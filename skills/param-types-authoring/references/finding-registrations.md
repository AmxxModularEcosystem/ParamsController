# Как найти регистрации типов в плагине

Цель — собрать полный список кастомных типов, которые регистрирует целевой
плагин, найти функцию-колбек каждого типа и функции-хелперы чтения.

## 1. Найти форвард регистрации

Плагин регистрирует типы в обработчике форварда `ParamsController_OnRegisterTypes`:

```pawn
public ParamsController_OnRegisterTypes() {
    // здесь регистрации
}
```

Поиск (регистр не важен):

```
ParamsController_OnRegisterTypes
```

## 2. Собрать вызовы регистрации

Внутри (и вокруг) форварда ищи нативы:

```
ParamsController_RegSimpleType
ParamsController_ParamType_Register
ParamsController_ParamType_SetReadCallback
```

- `ParamsController_RegSimpleType("TypeName", "@Callback")` — имя типа задано
  первым аргументом, функция чтения — вторым;
- `ParamsController_ParamType_Register("TypeName")` → возвращает хендлер, а
  функция чтения ставится отдельно через
  `ParamsController_ParamType_SetReadCallback(handle, "@Callback")`;
- имя типа может быть константой (`DEFAULT_PARAMS_*`-стиль или своя
  `stock const`), а не строкой-литералом — тогда найди её значение.

Если колбек передаётся именем, найди его определение по имени (`@Callback`),
даже если оно в другом файле.

## 3. Прочитать колбек

Сигнатура колбека чтения:

```pawn
bool:@OnReadMyType(const JSON:jValue, const Trie:tParams, const sParamKey[], const sParamTag[])
```

- `jValue` — JSON-значение параметра (источник допустимых форматов);
- `tParams` — Trie, куда пишется результат;
- `sParamKey` — ключ параметра;
- `sParamTag` — тег после `:` в имени типа (`Тип:тег`).

Колбек возвращает `true` при успехе и `false`, если значение некорректно.

## 4. Что смотреть внутри колбека

- **Разбор входа**: `json_get_type`, `json_is_array`, `json_is_object`,
  `json_is_string`, `json_array_get_number`, `json_object_get_number`,
  `json_object_has_value`, строковые форматы.
- **Запись результата**: `ParamsController_SetCell`, `ParamsController_SetString`,
  либо напрямую `TrieSetCell`, `TrieSetString`, `TrieSetArray`.
- **Тег**: ветки `equali(sParamTag, "...")`.
- **Побочные эффекты**: `precache_model` / `precache_sound` / `precache_generic`,
  `file_exists` / `dir_exists`, `regex_compile` и т.п.
- **Ошибки**: где возвращается `false` и с каким сообщением.
- **Мягкие преобразования**: `str_to_num` / `str_to_float` дают `0` без ошибки;
  отсутствующие поля объекта могут молча стать `0`.

## 5. Найти хелперы чтения

Потребителю нужно не только писать значение, но и читать его из `Trie`.
Стандартные хелперы контроллера — `PCGet_*` (чтение из результата) и
`PCSingle_*` (чтение одиночного значения из JSON) — есть всегда, но многие
плагины объявляют **собственные** функции для своих типов, иногда по тому же
образцу, иногда со своим префиксом.

Признаки таких функций:

- имя с префиксом `PCGet_` / `PCSingle_` или собственным префиксом плагина;
- на входе — `const Trie:p, const key[]` (геттер из результата) или
  `const JSON:valueJson` / `const JSON:objectJson, const key[]` (чтение из JSON);
- возвращают значение; вариант с `i` в имени возвращает временную строку.

Поиск:

```
PCGet_
PCSingle_
```

Для каждого типа отметь, чем он читается. Если своего хелпера нет — подставь
подходящий стандартный (`PCGet_Int`, `PCGet_iStr`, `PCGet_RGB`, `PCGet_Regexp`, …).

> Не считай, что набор ограничен стандартными хелперами контроллера: у плагина
> может быть свой слой функций чтения, и его тоже нужно описать.

## 6. Проверка полноты

Список типов считается полным, когда:
- найдены **все** вызовы регистрации в плагине (а не только в `plugin_init`);
- для каждого имени найдена функция чтения;
- известны все константы, использованные как имена типов;
- для каждого типа отмечен хелпер чтения (свой или стандартный);
- один и тот же текст на несколько типов вынесен в `references/_<группа>.md`,
  а не продублирован по файлам.

Регистрации могут быть разбросаны по файлам (частый приём — папка вида
`ParamType/<Тип>.inc`, где каждый файл регистрирует один тип). Просматривай
дерево `scripting/` целиком, а не один файл.

> Не путай типы плагина с типами его зависимостей: если колбек вида
> `ParamsController_RegSimpleType` лежит в коде другой библиотеки, которую
> подключают как dep, — это её тип, а не тип целевого плагина.

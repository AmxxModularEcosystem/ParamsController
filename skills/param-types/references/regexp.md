# Regexp

Регулярное выражение. При чтении строка **компилируется** (модуль `regex`
AMXX), и в Trie попадает хендлер скомпилированного выражения.

## Допустимые значения в JSON

Строка с регулярным выражением. Набор поддерживаемых конструкций — как в
модуле `regex` AMXX (PCRE-подобный синтаксис).

```json
"^vip_.*$"
```

## Что получится в Trie

Идентификатор (`handle`) скомпилированного `Regex` в виде числа. Используется
плагином для сопоставления строк — в конфиге вы просто задаёте шаблон.
Читается: `PCGet_Regexp` (+ `PCGet_RegexpMatch`).

## Когда будет ошибка

- выражение не компилируется (синтаксическая ошибка в шаблоне) — параметр
  некорректен, в лог пишется причина;
- значение не строка.

## Примеры

```json
{
    "NamePattern": "^[A-Za-z0-9_]+$",
    "VipTag": "^\\[VIP\\]"
}
```

> Экранирование в JSON стандартное: обратный слэш удваивается (`\\d`, `\\[`).
> Одна из частых ошибок — незакрытая группа `(` или `[` в шаблоне.

# Типы параметров ParamsController — сторона настройки

Этот скилл описывает **встроенные типы параметров** плагина
[ParamsController](https://github.com/AmxxModularEcosystem/ParamsController) с
точки зрения **заполнения JSON-конфига**, а не разработки плагина. Он отвечает
на вопрос: «параметр такого-то типа — какое значение сюда писать и что из него
получится».

## Как это устроено

1. Плагин объявляет набор параметров: **ключ** + **имя типа** + обязательность.
2. Контроллер читает значения этих ключей из **JSON-объекта** (обычно файл
   конфига плагина).
3. Для каждого параметра его тип определяет, какие JSON-значения допустимы, и
   **что будет записано в итоговое хранилище** (Trie) под этим ключом.
4. Дальше плагин берёт готовое значение из Trie.

Настраивая конфиг, вы влияете только на **значения в JSON**. Имя типа и ключ
задаёт сам плагин — их менять нельзя, а вот значение нужно привести к формату
своего типа.

> **Имена типов — точные строки.** Тип указывается ровно так, как зарегистрирован
> в контроллере (см. таблицу ниже), с учётом регистра. Например `PlayerModel`,
> а не `Player Model` или `playermodel`.

## Теги типов (`Тип:тег`)

Некоторым типам можно передать **тег** — имя типа пишется как `Тип:тег`
(разделитель `:`). Сейчас тег поддерживают ресурсные типы:

| Тип с тегом | Что меняется |
|---|---|
| `Model:index` | в Trie пишется не путь, а индекс прекеша (`precache_model`) |
| `Sound:index` | в Trie пишется индекс прекеша (`precache_sound`) |
| `Resource:index` | в Trie пишется индекс прекеша (`precache_generic`) |

Без тега эти типы пишут строку-путь. Конкретный тег задаётся в описании
параметра у плагина — со стороны конфига вы просто пишете путь/имя, как обычно.

## Обязательные и необязательные параметры, ошибки чтения

- **Обязательный параметр отсутствует в JSON** →
  `ParamsReadError_RequiredParamNotPresented`.
- **Значение некорректно для своего типа** → `ParamsReadError_ParamValueIsInvalid`.
  Возникает **даже для необязательного** параметра, если поле в JSON есть, но
  значение плохое.
- **Тип не зарегистрирован на момент создания параметра** → для обязательного
  это `ParamsReadError_UnknownParamType`, для необязательного — параметр тихо
  пропускается, даже если поле в JSON присутствует.
- **Чтение останавливается на первой ошибке.** В Trie попадут только параметры,
  прочитанные до неё. Поэтому одна опечатка в конфиге может «отрезать» все
  параметры, идущие после неё.

## Типы

Файл каждого типа лежит в `references/`. Открывайте **только те**, что нужны для
текущей задачи — не читайте весь справочник сразу.

| Тип (имя в конфиге) | Что это | Файл |
|---|---|---|
| `Boolean` | логическое `true`/`false` (+ строковые и числовые варианты) | `references/boolean.md` |
| `Integer` | целое число | `references/integer.md` |
| `Float` | число с плавающей точкой | `references/float.md` |
| `ShortString` | строка до 64 ячеек | `references/short-string.md` |
| `String` | строка до 512 ячеек | `references/string.md` |
| `LongString` | строка до 4096 ячеек | `references/long-string.md` |
| `RGB` | цвет (R, G, B) | `references/rgb.md` |
| `Model` | существующая модель + прекеш | `references/model.md` |
| `PlayerModel` | имя модели игрока (`models/player/<name>/<name>.mdl`) | `references/player-model.md` |
| `Sound` | существующий звук (`sound/...`) + прекеш | `references/sound.md` |
| `Resource` | существующий ресурс + прекеш (`precache_generic`) | `references/resource.md` |
| `File` | существующий файл (без прекеша) | `references/file.md` |
| `Dir` | существующая директория | `references/dir.md` |
| `ChatMessage` | строка чата до 190 ячеек с цветами `^1`/`^3`/`^4` | `references/chat-message.md` |
| `Flags` | флаги доступа AMXX → битовая маска | `references/flags.md` |
| `Time` | время суток `HH[:MM[:SS]]` → секунды от полуночи | `references/time.md` |
| `TimeInterval` | интервал (`1d12h30i30`) → секунды | `references/time-interval.md` |
| `WeekDay` | день недели (рус/англ) → номер `0..6` | `references/week-day.md` |
| `Regexp` | регулярное выражение → скомпилированный хендлер | `references/regexp.md` |

## Общие правила и подводные камни

- **Пути — относительно `cstrike/`** (для `Model`, `Resource`, `File`, `Dir`),
  а у `Sound` — относительно `cstrike/sound/` (контроллер сам подставляет
  `sound/`). Используйте прямые слэши `models/v_ak47.mdl`.
- **`File`/`Dir`/`Model`/`Sound`/`Resource` обязательно проверяют существование**
  файла на сервере. Нет файла — параметр некорректен. Это самая частая причина
  «конфиг правильный, а параметр не читается».
- **`Model`/`Sound`/`Resource`/`PlayerModel` кладут файл в прекеш** в момент
  чтения. Это влияет только на ресурсы сервера, от вас — корректный путь.
- **`TimeInterval`: `m` — это месяцы (30 дней), а не минуты.** Минуты — `i`.
  Год (`y`) считается как 360 дней.
- **`Time` и `WeekDay` — это разные вещи.** `Time` — время суток (напр. `"6:30"`),
  `WeekDay` — день недели (напр. `"Пн"`).
- **`Integer`/`Float` из строки не падают с ошибкой**: нечисловая строка
  превращается в `0`/`0.0`. Если значение молча стало нулём — проверьте строку.
- **`Boolean` строг к строкам**: неизвестная строка — ошибка чтения (в отличие
  от чисел).
- **`ChatMessage` ограничен 190 ячейками** (≈190 латинских символов; кириллица
  «весит» вдвое). Слишком длинная строка обрезается.
